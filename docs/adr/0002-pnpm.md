# ADR-0002 — pnpm comme gestionnaire de paquets

- **Statut :** accepté
- **Date :** 2026-09-30

## Contexte

RDC v1 utilisait npm. Le nouveau workspace part de zéro.

## Décision

- pnpm, version fixée par le champ `packageManager` de `package.json`
  (activée par Corepack en local et par `pnpm/action-setup` en CI).
- `pnpm install --frozen-lockfile` en CI : un lockfile désynchronisé fait
  échouer la pipeline.
- Les dépendances qui exécutent un script d'installation doivent être
  autorisées explicitement dans `onlyBuiltDependencies` (`pnpm-workspace.yaml`).
  À ajouter avec Prisma : `@prisma/engines`, `prisma`.
- Les libs sont référencées par alias TypeScript (`paths` dans
  `tsconfig.base.json`, ex. `@rdc/referentiel-domain`), comme le génère le
  preset Nest de Nx.

## Conséquences

- Commandes : `pnpm nx …` au lieu de `npx nx …`.
- Les libs partagent le `node_modules` racine : l'isolation stricte de pnpm ne
  protège pas les couches. Ce rôle est tenu par le lint (ADR-0003, règle R2).
